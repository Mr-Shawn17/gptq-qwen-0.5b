## 1. 最终结果总览

### 1-1 性能对比（同口径：OpenAI API / HTTP / 流式 / 同 prompt / **max_tokens=1024 自然收尾** / temp=0 / 预热3+5次中位数，2026-10-22 测）

| 指标 | BF16 基线（服务 FP16） | 官方 GPTQ（W4A16） | **自产 GPTQ（W4A16）** | 自产 vs BF16 基线 |
|---|---|---|---|---|
| 纯解码速度 (tok/s) | 23.34 | 59.54 | **59.87** | **+156%（2.56 倍）** |
| TTFT (ms) | 220.5 | 65.4 | **60.2** | 快 3.7 倍 |
| 自然输出长度 (tok) | 308 | 339 | **129** | 见观察点② |
| 显存峰值 (MiB) | 2031 | 2132 | **2132** | +5%（可接受） |
| 模型体积 (MB) | 988 | 699 | **439** | **-56%** |

> 与官方 GPTQ 对照：解码速度 +0.6%（59.87 vs 59.54，长输出下两者收敛到同一 kernel 稳态）、TTFT 再降 8%（60.2 vs 65.4）、体积再省 37%（439 vs 699）。
> **总耗时不再作为横向对比行**：三组自然输出长度不同（308/339/129 tok），端到端耗时不具可比性，速度对比以解码 tok/s 为准；各组逐次总耗时见 1-1-1 明细表。
> **dtype 口径说明**：基线模型权重本身是 BF16，因图灵卡（GTX 1650）无 BF16 计算单元，vLLM `--dtype half` 加载时自动转换（日志铁证：`Casting torch.bfloat16 to torch.float16`，最终引擎 dtype=torch.float16）。两个 GPTQ 产物同为 W4A16：权重存储 INT4，激活/反量化计算 FP16。量化阶段（阶段 2）则是 BF16 原生加载（`Loader: Auto dtype (native bfloat16)`）。
> **口径沿革**：首轮测试为 max_tokens=128（输出全部被上限截断，finish_reason=length），数据存档于 `bench_results/*_http.json`；本报告测试结果统一采用 1024 自然收尾口径（`bench_results/*_1024.json`）。
> **核心结论：GTX 1650 上 GPTQ W4A16 走 vLLM 是当前最优推理方案——长输出解码速度 2.56 倍于基线，体积省 56%。**

### 1-1-1 逐次明细（max_tokens=1024，全部自然收尾；源自 bench_results/*_1024.json 的 samples 原始记录）

同 prompt（"请用两百字介绍一下人工智能的发展历史，要求逻辑清晰、分阶段说明。"，输入 37 tok）/ 流式 / temp=0 / 预热 3 + 正式 5 次取中位数。测试脚本隔离在 `~/quant_gptq/scripts/`（bench_openai.py 副本 + run_bench_1024.sh），未触碰其他任务脚本。
> **bench 口径说明**：性能测试采用 bench_openai.py 的 **v1 单题模式**——同一道题重复 5 次取中位数，消除题间方差；**五道不同的题**用于 1-2 质量对照（v2-bank 模式），两套口径各司其职。

**观察点（长输出自然收尾下的稳态表现）**：

1. **三组全部自然收尾（stop），无一截断**——max_tokens=1024 足够模型自然停笔，输出长度由模型自己决定。
2. **输出长度分化明显**：同一道"两百字"题，BF16 写 308 tok（约 450 字，超纲）、官方 GPTQ 写 339 tok（超纲更甚）、自产 GPTQ 写 129 tok（约 190 字，**最贴近题目"两百字"要求**）。量化改变了生成策略的收敛行为——从指令遵循角度这是质量差异的新信号，但单题样本不足以定论，仅作观察记录。
3. **长输出解码速度是 kernel 稳态**：BF16 受 KV cache 随长度增长拖累（308 tok 时 23.34 tok/s）；两个 GPTQ 收敛到 59.5~59.9 tok/s，高度一致——这就是 W4A16 反量化 kernel 在长输出下的真实稳态。
4. **结论**：自产 GPTQ 解码速度是 BF16 基线的 **2.56 倍**（59.87 vs 23.34），TTFT 快 3.7 倍（60.2 vs 220.5ms），体积省 56%——GTX 1650 上 GPTQ W4A16 走 vLLM 是当前最优推理方案。

## 5. 日常使用速查（自产 GPTQ 模型）

```bash
# WSL 内启动自产 GPTQ 服务
source ~/miniconda3/etc/profile.d/conda.sh && conda activate vllm
export VLLM_USE_V1=0
vllm serve ~/quant_gptq/models/Qwen2-0.5B-Instruct-GPTQ-Int4-local \
    --served-model-name qwen2-gptq-local --dtype half --quantization gptq \
    --gpu-memory-utilization 0.6 --max-model-len 2048 --port 8000
# 注意：--quantization gptq 必须带（否则 vLLM 自动切 bitblas 后端报错）

curl http://localhost:8000/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model":"qwen2-gptq-local","messages":[{"role":"user","content":"你好"}],"max_tokens":32}'
```
